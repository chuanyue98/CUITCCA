## 语料构成

知识库有两类来源，各自解决不同问题：

| 来源 | 位置 | 性质 | 解决什么 |
|---|---|---|---|
| 静态归档 | `信息搜集汇总/` | 人工搜集的历史文档（PDF/Word/Excel/图片） | 规章制度、办事流程、表单模板——这些内容官网上往往是附件下载，爬不到正文 |
| 动态站群 | `data/corpus/web/`（爬取产出） | CUIT 官网及二级站点公开页面 | 通知公告、新闻、学校概况——时效性内容，静态归档做不到持续更新 |

两者最终进同一套摄取管道（`backend/app/handlers/ingestion_pipeline.py`），共用同一套解析器注册表和去重逻辑。

## 静态语料：信息搜集汇总

257 个文件、118MB，覆盖招生、就业、学生服务、生活服务、学习资源、后勤等主题。

### 格式分布与解析覆盖

| 扩展名 | 数量 | 状态 |
|---|---|---|
| `.txt` | 118 | ✅ |
| `.pdf` | 55 | ✅ 含表格结构化抽取 |
| `.json` | 29 | ⛔ **刻意排除**——旧版 llama_index 持久化产物（`docstore.json` 等），不是知识内容 |
| `.docx` | 24 | ✅ 23 成功 / 1 失败（文件本身损坏，见下） |
| `.doc` | 17 | ⚠️ 可解析但标记降级（OLE2 启发式提取） |
| `.jpg` | 4 | ✅ OCR（需 `uv sync --extra ocr`） |
| `.xlsx` | 4 | ✅ |
| `.pptx` | 2 | ✅ 保留幻灯片序号 |
| `.xls` | 2 | ✅ |
| `.csv` | 1 | ✅ |

**改造前只支持 6 种格式**（`pdf/docx/txt/md/csv/xlsx`），其余 54 个文件（21%）在上传白名单阶段就被挡掉且**没有任何提示**。现在可摄取文件从 203 提升到 228（79% → 89%），新增 25 个文件、约 16,000 字符进入知识库。

### 已知数据质量问题

采集过程中发现的问题，如实记录而不是掩盖：

- **5 个完全空的文件**，且恰好是高频问题的来源：
  - `招生信息/成都信息工程大学录取政策.txt`
  - `就业信息/就业指导中心联系方式.txt`（及其副本）
  - `招生就业（dyc）/招生录取/成都信息工程大学录取政策.txt`
  - `社团信息.txt`
- **21 个文件小于 200 字节**，多为单行的部门电话
- **1 个 docx 损坏**：`后勤服务电话2022.12.docx` 缺少 OOXML 关系定义，python-docx 无法打开。同目录的 `.doc` 版本能正常解析出 990 字符，内容未丢失
- **大量重复**：同一份文档在多个子目录镜像存在（`information/`、`学校信息(wd)/` 等），由摄取管道的内容 sha256 去重处理
- **内容陈旧**：`学校简介.txt` 写"61个本科专业、2.5万在校生"，而官网现值是"52个招生本科专业、在籍学生30000余人"——这正是需要动态采集补充的原因

## 动态语料：Web 连接器

### 架构

```
sites.yaml (配置)  →  WebConnector.discover()  →  SourceRef 列表
                              ↓
                      WebConnector.fetch()      →  CrawledDocument
                              ↓
                      markdown_io.write()       →  .md + YAML front-matter
```

**配置驱动**：站点、栏目、URL 模板、分页规律、正文选择器全在 `backend/app/connectors/sites.yaml`，新增栏目或站点只改这个文件，不动代码。

### 站点覆盖

| 站点 | 域名 | 状态 |
|---|---|---|
| 学校官网 | `www.cuit.edu.cn` | ✅ 学校概况 / 组织机构 / 师资队伍 / 科学研究 / 成信要闻 / 综合新闻 / 通知公告 / 成信学术 |
| 教务处 | `jwc.cuit.edu.cn` | ✅ 创新创业 / 通知公告 |
| 国际合作与交流处 | `gjjl.cuit.edu.cn` | ✅ 关于我们 / 国际教育 / 海外交流 / 港澳台事务 |
| 国内合作处（校友办） | `xyw.cuit.edu.cn` | ✅ 部门概况 / 国内合作 / 通知公告 |
| 本科招生网 | `zjc.cuit.edu.cn` | ❌ **网络不可达**（TLS 握手失败 / HTTP 000），已在配置中 `enabled: false` 并注明原因 |
| 网上办事大厅 | `ywtb.cuit.edu.cn` | ❌ 纯前端 SPA，静态抓取拿不到内容，需无头浏览器，超出当前连接器范围 |

主站与 `jwc`/`gjjl`/`xyw` 共用同一套"网站群"CMS 模板，因此选择器可共享：

- 详情页：`base_url/info/<栏目ID>/<文章ID>.htm`
- 正文容器：`div.v_news_content`（外层 `div#vsb_content` → `div.article`）
- 标题：`h2.tit`；日期：`p.conttime`
- 列表项：`ul.list > li > a[href]`，标题在 `title` 属性，日期在内层 `<span>`
- **分页是倒序编号**：第 1 页是 `<index>.htm`，第 2 页起是 `<index>/<N-1>.htm` 递减到 `<index>/1.htm`（N 为总页数，运行时从翻页控件自动解析）

### 实际采集结果（2026-08-08，`--max-pages 10`）

| 站点 | discovered | fetched | failed |
|---|---:|---:|---:|
| main | 607 | 528 | 76 |
| jwc | 3 | 3 | 0 |
| gjjl | 7 | 7 | 0 |
| xyw | 5 | 5 | 0 |
| **合计** | **622** | **543** | **76** |

产出 **546 个 Markdown 文件、约 3.0MB**，时间跨度覆盖到 2026-08。

#### 那 76 条失败是什么

集中在主站 `info/1007`（成信学术栏目，72/76）。查过原始 HTML：**正文容器
`div.v_news_content` 是命中的，但里面只有一张海报 `<img>`，文本长度为 0**——
学术报告预告这个栏目的内容全部做在图片里。

这不是选择器配错，也不是 bug：连接器拒绝写入空文档是正确行为。但早期版本
统一把这类情况报成"正文选择器未命中"是**误导性的**，会让人跑去改配置找不存在
的问题，现在日志措辞已区分"选择器没命中"和"命中了但容器内没文字"两种情况。

理论上这些海报可以用项目已有的 OCR 能力提取（`uv sync --extra ocr`），属于
后续扩展方向，当前未做。

### 产出格式

每页一个 Markdown 文件，头部是 YAML front-matter：

```markdown
---
source_url: https://www.cuit.edu.cn/info/1002/15476.htm
title: 何建新出席2025年全国气象观测工作会议
publish_date: '2025-11-04'
category: 成信要闻
site: main
crawled_at: '2026-08-08T06:32:46+00:00'
content_hash: 574c539c...
---

# 何建新出席2025年全国气象观测工作会议

【本网讯】11月3日至4日，...
```

这些 metadata 不是装饰——摄取时会被**提升为节点 metadata**（见 `backend/app/handlers/parsers/front_matter.py`），用于检索过滤和回答里的引用溯源。两个关键设计：

- `last_updated` 优先取 `publish_date` 而非文件落盘时间。后者对爬取语料全都是"抓取当天"，完全没有区分度，做不了时效性过滤。
- `doc_id` 只按**正文**算 sha256，**不含 front-matter**。否则 `crawled_at` 每次抓取都变 → `doc_id` 每次都变 → `DocstoreStrategy.UPSERTS` 永远判定"这是新文档"，增量摄取彻底失效。

**文件名只由 URL 派生，不掺标题**：标题被网站编辑改一个字（比如加"【已结束】"前缀）就会算出新文件名，产生孤儿文件，同一页面在语料库里留下两个版本。

## 采集复现

```bash
# 先试跑：只做 discover，不请求详情页、不写文件
uv run python scripts/crawl_cuit.py --dry-run --max-pages 2

# 正式采集（列表类栏目每个最多翻 10 页）
uv run python scripts/crawl_cuit.py --max-pages 10

# 只抓某个站点 / 某个栏目
uv run python scripts/crawl_cuit.py --site main --section tzgg
uv run python scripts/crawl_cuit.py --site jwc

# 忽略增量记录强制全量重抓
uv run python scripts/crawl_cuit.py --mode full
```

采集产物落在 `data/corpus/web/`，增量状态在 `data/corpus/web/.crawl_state.json`。

把采集结果导入知识库：

```bash
uv run python scripts/ingest_cori_online.py --source-dir data/corpus/web --index-name campus-web
```

## 增量更新策略

按 **URL → 正文 sha256** 判重，记录在 `.crawl_state.json`：

- 正文没变 → 跳过，不重写文件、不占带宽（`skipped_unchanged`）
- 正文变了 → 覆盖同名文件（文件名由 URL 稳定派生），更新 hash
- 状态文件损坏 → 退化成全量抓取而不是崩溃
- 状态保存用"临时文件 + 原子替换"，避免抓到一半被杀留下截断的 JSON

实测：连续两次运行同一组栏目，第二次 `fetched=0, skipped_unchanged=3`。

### 礼貌抓取

| 机制 | 配置 | 说明 |
|---|---|---|
| 请求间隔 | 1.2s | 全局限速，锁保护，多线程安全 |
| 并发上限 | 2 | |
| 超时 | 15s | |
| 重试 | 最多 3 次 | 指数退避 + 抖动，**只对网络类异常重试**（代码 bug 不该被当成网络抖动反复重试） |
| robots.txt | 每站点拉一次并缓存 | CUIT 官网实测无 robots.txt（404），按标准约定视为未声明限制 |
| User-Agent | 标识 bot + 项目地址 + 非商业声明 | **必须纯 ASCII**——HTTP header 不允许非 ASCII，写中文会直接 `UnicodeEncodeError` 崩掉 |

## 数据时效性

- 静态归档：多为 2018–2023 年文档，**已明显过时**（专业数、在校生数与官网现值不符）
- 动态采集：覆盖到 2026-08，通知公告类内容最新
- 回答时效性依赖节点 metadata 的 `last_updated` / `publish_date`

**重要**：知识库不含 2026 年校历、当年录取分数线、实时课表等信息。这类问题应当明确拒答并引导到官方渠道，而不是编造——`evals/golden.refusal.jsonl` 里专门有一组题（`not_in_corpus`）覆盖这个行为。

## 已知缺口

1. **本科招生网抓不到**（`zjc.cuit.edu.cn` 网络不可达）——这是校园助手最有价值的内容之一。静态归档里有部分招生文档可部分弥补。
2. **网上办事大厅是 SPA**，静态抓取无效，需引入无头浏览器。
3. **各学院二级站点未纳入**——19 个学院各有独立站点，结构可能与主站模板不同，需逐个探测。
4. **附件未跟进下载**：通知公告里的 PDF/Word 附件目前只抓正文页，附件本身没下载解析。这是后续最有价值的扩展方向（很多实质内容都在附件里）。
5. **跨页表格**：PDF 里跨页的大表格会被当成两个独立表格，第二段没有表头。

## 合规声明

- 只采集**公开可访问**的页面，不涉及任何需要登录、鉴权的内容，不触碰个人信息
- 遵守 `robots.txt`；无 `robots.txt` 时按标准约定视为未声明限制
- 限速 1.2s/请求、并发 2，远低于正常浏览强度，不对目标站点造成压力
- User-Agent 明确标识爬虫身份、项目地址与非商业用途，便于站点管理员识别与联系
- 采集内容仅用于**非商业的学习/演示项目**，不做再分发

**采集产物不进版本库**：`/data/` 已在 `.gitignore` 中。爬取内容的著作权属学校，在公开仓库中重新分发存在风险；仓库只保留采集**能力**（配置 + 代码 + 复现命令），数据由使用者自行采集。
